# Qwen3-0.6B runner handoff
Proposed interface for a separately operated local inference process. This milestone defines a file exchange; the dashboard and CI have no runner client or service controls.

1. Before implementation, agree on the split, schema, prompt and run manifest. Export a request JSONL containing only case_id and source_text. Supply a fixed public schema and prompt separately. Keep expected labels, evidence and the answer key on the scoring side.
2. The operator approves execution independently and retains control of the runner, limits and stop conditions. Record the model artifact revision and digest, quantization, runtime version, template, thinking mode, sampling settings, seed if supported, token limit, input hashes and run ID. Use existing operational protections. Abort on an operator stop or protection event. Never retry automatically.
3. Return one JSONL record per case with case_id, status, raw_text and elapsed_ms. Keep raw_text verbatim, including malformed JSON or reasoning text. Use an explicit timeout/error status with null raw_text when no response exists. Reject duplicate, unknown or missing IDs. Report attempted, completed, errored and timed-out counts before scoring. Report both completed-only metrics and all-attempt denominators.
4. Implement the offline importer first. Use clearly labeled mock records for success, malformed output, wrong value, timeout, duplicate and missing IDs. For completed responses pass raw text to the existing scorer; define separately how extra fields, missing values and exact-match semantics affect the model report. Keep raw artifacts and operational metadata private by default. Publish only reviewed, redacted aggregates.
5. After explicit approval, a small development run can validate the exchange. A held-out evaluation requires a separately frozen split and protocol. Never replace the seeded dashboard report with runner output. The legacy Ollama config names another model and is outside this workflow.
